# verification-hub

[English](./README.en.md)

運営者のリポジトリに共通する検査を、変更のたびに回す仕組みを置くリポジトリです。
仕組みは、GitHub Actions の再利用のワークフロー [shared-check.yml](./.github/workflows/shared-check.yml) です。
目録で caller が hub の欄のリポジトリは、push と PR のたびに、このワークフローをコミットの値で固めて呼びます。
読むリポジトリと、各リポジトリで回す検査の手順は、目録の [repos.json](./repos.json) にあります。
いま目録にあるのは、運営者の 15 のリポジトリと、このリポジトリ自身です。
サイトは持ちません。
このリポジトリの道具は、外のパッケージを使いません。
道具は Node.js 22 で動きます。

## 確かめ方と、ハブが回すもの

運営者の決めごとは、報告やマージの前に、合っているかを互いに独立した 10 のやり方で確かめると定めています。
そのうち、機械で回せるものをハブが回します。
人か別の担当が行うものは、ハブの外に残ります。

| 番号 | やり方 | ハブ |
| --- | --- | --- |
| 1 | そのリポジトリの検査を走らせる | 回す（own の仕事。各リポジトリの CI と同じ手順） |
| 2 | 横断の検査を走らせる | 回す（common の仕事。目録の cross が true の欄だけ。正本を持つリポジトリの check_all.js と check_ecosystem.js） |
| 3 | CI の結果を見る | 結果を出す（見るのは人か別の担当） |
| 4 | 元の資料と差分を読み直す | 回さない |
| 5 | 一次の出典と突き合わせる | 回さない |
| 6 | 数を自前の台本で計算し直す | 回さない |
| 7 | 壊して落ちることを確かめる | 回す（各リポジトリの CI が持つ --break と、このリポジトリの検査の --break） |
| 8 | 全リポジトリを同じ型で検索する | 回す（common の仕事。メールアドレスと壊れた活用の走査） |
| 9 | 他の言語版・写し・生成元と突き合わせる | 回す（common の仕事。正本の写しの一致と、ファイルのつながり） |
| 10 | 結論を渡さずに別の担当に確かめさせる | 回さない |

10 のやり方のうち、ハブが回すのは 5 つです。
CI の結果は、ハブが出し、見るのは外の手です。
残る 4 つは、ハブの外に残ります。

## 仕事

ワークフローは三つの仕事を持ちます。

- plan は、目録を読み、呼んだリポジトリの検査の仕事を並べます。
- own は、呼んだリポジトリの CI の検査を、目録の手順のとおりに一つずつ回します。
- common は、目録のリポジトリを読むだけの複製として並べ、どのリポジトリにも同じ物差しを当てる検査を回します。
- common は、目録の cross が true の欄でだけ、横断の検査を回し、すべてのリポジトリを走査します。
- common は、cross が false の欄では、呼んだリポジトリだけを走査します。

own の手順は、各リポジトリの CI のワークフローのうち、push か PR で起きる仕事の手順を写したものです。
写さない仕事は、目録の not_carried に理由と並べてあります。
配備や記録の仕事、issue で動く仕事、外の API に問い合わせる仕事が、それに当たります。
写す仕事も、各リポジトリの CI と同じく、PyPI・npm・apt・Playwright の配る場からパッケージやブラウザを入れます。
このリポジトリの検査が、目録の手順と各リポジトリの main のワークフローを一つずつ照らします。

## 呼び方

呼ぶ側は、[templates/hub.yml](./templates/hub.yml) を自分の `.github/workflows/` に写します。
雛形は、このリポジトリのコミットの値でワークフローを固めて呼びます。
ワークフローは、GitHub Actions の `job.workflow_sha` を使い、道具と目録を、自分と同じコミットから読みます。
そのため、このリポジトリの main が変わっても、呼ぶ側が値を上げるまで、ワークフロー・道具・目録は変わりません。
ただし、並べるリポジトリと横断の検査は、実行のときの各リポジトリの既定の枝から読みます。
そちらが動けば、同じ値でも結果は変わりえます。
入力も鍵も渡しません。
注釈の版（v1）は、呼び方の版です。

## 守り

| 守り | 確かめ方 |
| --- | --- |
| 権限は contents: read だけ | ワークフローの全体の権限を読み、仕事ごとの権限と書く権限が無いことを見る |
| 鍵を読まない | secrets・github.token・GITHUB_TOKEN の語が無いことを見る |
| 外のアクションをコミットの値で固める | uses の値がコミットの値と版の注釈を持つことを見る |
| どの仕事にも時間の上限がある | 仕事ごとの timeout-minutes を読み、上限を超えないことを見る |
| run の行に式を書かない | run の行に式が無く、出来事の値は checkout の ref にだけあることを見る |
| 同時実行の組を呼ぶ側の仕事に置く | 呼ぶ側の仕事の組と、ワークフローの側に組が無いことを見る |
| pull_request_target と workflow_run で起こさない | 起こす出来事を読み、二つの語が無いことを見る |
| checkout が鍵を残さない | どの checkout も persist-credentials: false を持つことを見る |
| 道具を同じコミットから読む | 道具の checkout が job.workflow_repository と job.workflow_sha を読み、その前に値を確かめることを見る |
| 道具とワークフローにリポジトリの名を書かない | 目録の名が、道具とワークフローに無いことを見る |

どの守りも、[verification/check.js](./verification/check.js) が確かめます。
`--break` を付けると、守りを一つずつ壊し、どれでも検査が落ちることを確かめます。

## 写しの置き方

目録で caller が self-contained の欄のリポジトリは、このリポジトリを呼びません。
そのリポジトリは、同じワークフローの一字一句同じ写しと、道具の写しと、自分の欄だけの目録と、道具のライセンス（MIT）の写しを持ちます。
写しの置き方では、そのリポジトリの検査と、メールアドレスの走査と、ファイルのつながりだけを回します。
横断の検査は、ほかのリポジトリが呼ぶハブの側で、そのリポジトリを読んで回ります。
理由は [docs/decisions.md](./docs/decisions.md) にあります。

## 検査

```
node verification/check.js                          # 守り・目録の形・雛形・散文
node verification/check.js --break                  # 検査を一つずつ壊し、落ちることを確かめる
node verification/check.js --repos <並べた置き場>      # 加えて、目録と各リポジトリの CI、正本の写し
GITHUB_REPOSITORY=<持ち主>/<名> node tools/common.js <並べた置き場>   # 写し・走査・つながり
```
