# 決めたこと

このリポジトリを作るときに、Claude が決めたことと、その理由を並べます。
2026-11-19 に利用者が仕組みを求め、同じ日に Claude が決めて書きました。
同じ日の独立の点検の指摘を受けて、横断の検査を回す範囲、SECURITY.md、同時実行の組、定期の実行、写しのライセンスの節を足しました。

## 道具を、ワークフローと同じコミットから読む

ワークフローは、道具と目録を `job.workflow_repository` と `job.workflow_sha` の値で取り出します。
GitHub の説明書は、これらの値が、仕事を定めたワークフローのファイルのリポジトリとコミットを指すと書いています。
説明書の文は、`github/docs` のコミット `8e818157d80f08e711a78621c28f8d169d158444` の `content/actions/reference/workflows-and-actions/contexts.md` から、2026-11-19 に読みました。
同じ頁は、再利用のワークフローが自分のファイルを取り出す例として、これらの値を挙げています。
呼ぶ側はワークフローをコミットの値で固めるので、ワークフローと道具と目録は、そのコミットのものだけが動きます。
入力で値を渡す形は採りませんでした。
入力の値とワークフローの値が食い違えば、固めていない道具が動くためです。
値は、取り出す前に、形を確かめます。
値が空なら、取り出しは既定の枝に落ちるので、その前に止めます。

固めた値が守るのは、このリポジトリのファイルだけです。
並べる兄弟のリポジトリと、正本を持つリポジトリの横断の検査は、実行のときの各リポジトリの既定の枝から読みます。
そちらが動けば、同じ固めた値でも結果は変わりえます。
正本を持つリポジトリのコミットの値まで固める形は、採りませんでした。
横断の検査は、各リポジトリのいまの文を突き合わせる検査なので、古いコミットで回すと、いまのずれを見落とすためです。

## 呼ぶ側の仕事に、時間の上限を置かない

GitHub の説明書は、再利用のワークフローを呼ぶ仕事に置ける語を挙げています。
`timeout-minutes` は、その中にありません。
説明書の文は、同じコミットの `content/actions/reference/workflows-and-actions/reusing-workflow-configurations.md` から読みました。
時間の上限は、呼ばれるワークフローの三つの仕事に置きます。
運営者のほかのリポジトリの検査は、どの仕事にも時間の上限を求めています。
呼ぶ仕事をその外に置く直しは、取り込みのときに、そちらの検査に足します。

## 写す仕事と、写さない仕事

写すのは、各リポジトリの CI のワークフローのうち、push か PR で起きる仕事です。
目録の手順は、ワークフローを読んで写しました。
写さないのは、形の上で写せない仕事と、外の API に問い合わせる仕事です。
形の上で写せない仕事は、仕事の if・書く権限・このリポジトリの Action・式で読む出来事や鍵を持つ仕事です。
どれに当たるかは、検査がワークフローから読んで確かめます。
外の API に問い合わせる仕事は、DataCite に問い合わせる仕事です。
これは検査がワークフローから読み分けられないので、目録に理由を書いて決めました。
写す仕事も、PyPI・npm・apt・Playwright の配る場から、パッケージやブラウザを入れます。
それは、各リポジトリの CI が同じ手順で入れているものと同じです。
横断の検査の仕事は、own ではなく common の仕事として回します。
写す仕事は、各リポジトリの CI でも回り続けます。
同じ手順が各リポジトリの CI とハブの両方で回るので、実行の時間はおよそ倍になります。

## 横断の検査を回すリポジトリ

GitHub の追加製品の規約の Actions の節は、GitHub の実行環境の使い方を、そのリポジトリのソフトウェアの制作・検査・配備・公開に限ります。
この読みを、呼ぶ側のどのリポジトリにも同じに当てます。
横断の検査（正本を持つリポジトリの `check_all.js` と `check_ecosystem.js`）は、ほかのリポジトリの検査を丸ごと回します。
それがそのリポジトリの検査に当たるのは、そのリポジトリの文が、ほかのリポジトリの数と事実を名乗り、横断の検査がそれを確かめるときです。
正本を持つリポジトリの `verification/ecosystem.json` の「共通の決めごと」が挙げるリポジトリは、決めごとを分け合い、互いの数を名乗り合っています。
そのリポジトリと、横断の検査を道具に持つこのリポジトリ自身だけが、目録で `cross` を true にします。
ほかの呼ぶ側では、横断の検査を回しません。
そこでは、自分の検査と、自分のファイルの写し・宛先・壊れた活用・つながりの走査だけを回します。
ほかのリポジトリは、写しの正本とリンクの行き先を読むためだけに、読むだけの複製として並べます。
`cross` が true の欄が、正本を持つリポジトリの挙げる並びと同じことは、検査が照らします。

## 分けておくリポジトリ

目録で caller が self-contained の欄のリポジトリは、研究の系列の名やリンクを自分に書かず、研究の系列からもつながない決まりを持ちます。
目録にそのリポジトリの名を置くことは、この決まりを破らないと決めました。
目録は機械が読む表で、読む人のためのリンクではありません。
同じ運営者の横断の検査は、もう同じ形でそのリポジトリを読んでいます。
そこでは、ワークフローの取り出しと、ワークフローの表に名を置き、散文には書いていません。
このリポジトリも、名は目録の鍵にだけ置き、散文には書きません。
一方で、そのリポジトリがこのリポジトリを呼ぶ形は採りませんでした。
呼べば、そのリポジトリのワークフローに、研究の系列の側にあるこのリポジトリの名が入るためです。
横断の検査は、上の節の読みのとおり、そのリポジトリでも回しません。
そのため、そのリポジトリは、同じワークフローの写しと道具の写しを持ち、自分の欄だけの目録で、自分だけを検査します。
写しのワークフローと道具には、どのリポジトリの名もありません。
そのリポジトリのライセンスは CC BY 4.0 だけなので、道具のライセンス（MIT）の写しも、道具と同じ場所に置きます。
検査は、写しがそろったとき、その写しが `LICENSE-CODE` と一字一句同じことを見ます。
横断の検査は、ほかのリポジトリが呼ぶハブの側で、そのリポジトリを読むだけの複製として読みます。

## SECURITY.md を写しにしない

運営者の SECURITY.md の正本は、文書と手元で動くスクリプトと静的な頁を持つリポジトリのために書かれています。
Actions を持つのはほかのリポジトリだけと書いてあり、ほかのリポジトリの Actions の中で動くこのリポジトリのワークフローに合いません。
そのため、このリポジトリの SECURITY.md は、正本の写しにせず、このリポジトリのことを書いた文にしました。
宛先は正本と同じで、運営者の ORCID の記録にあるメールアドレスです。
宛先そのものは書きません。
GitHub の非公開の脆弱性報告が有効でないことは、2026-11-19 に GitHub の API で確かめました。
写しの一覧（`verification/copies.json`）と、目録のこのリポジトリの写しの欄からは外しました。
検査は、この文が正本と違うことと、宛先の道と確かめた日を持つことを見ます。

## 同時実行の組

GitHub の説明書は、同じ組で待っている実行を、新しい実行が取り消すと書いています。
説明書の文は「By default, any existing `pending` job or workflow in the same concurrency group will be canceled and the new queued job or workflow will take its place.」です。
文は、同じコミットの `data/reusables/actions/actions-group-concurrency.md` から読みました。
cancel-in-progress を false にしても、待っている実行は取り消されます。
そこで、組の名を、PR では PR の枝ごと、ほかでは実行ごとにしました。
PR では、新しい push の実行が古い実行を取り消します。
main への push と定期と手で起こした実行は、どれも自分だけの組に入り、取り消されません。

## 定期の実行

このリポジトリの自己検査（self-test.yml）は、週に一度も回ります。
目録の手順と各リポジトリの CI のずれは、このリポジトリに変更が無い日にも起きるためです。
GitHub の説明書は、公開のリポジトリの定期の実行が、動きの無いまま日がたつと止まると書いています。
説明書の文は「In a public repository, scheduled workflows are automatically disabled when no repository activity has occurred in 60 days.」です。
文は、同じコミットの `content/actions/reference/workflows-and-actions/events-that-trigger-workflows.md` から読みました。
このリポジトリに動きの無い日が続けば、週に一度の実行は止まります。
運営者の見張り（正本を持つリポジトリの heartbeat）が読むリポジトリの並びに、このリポジトリはいま入っていません。
そのため、止まったことは、いまはどの見張りにも拾われません。

## 走査で外したもの

メールアドレスの形に合っても、宛先ではないものを二つ外しました。
一つは、すぐ後ろに丸括弧か角括弧が続くものです。
Python の行列の積と関数の呼び出しが、この形になります。
もう一つは、iCalendar のファイルの UID の行です。
UID は、宛先の形を借りた一意の名で、宛先ではありません。
許す宛先は、正本を持つリポジトリの `verification/check_secrets.js` の表から読みます。
リポジトリごとに許す宛先は、宛先を書かずに SHA-256 で目録に置きます。
どれも、そのリポジトリの検査が許しているものだけです。

## 横断で止める活用の形

壊れた活用の形は、正本を持つリポジトリの `verification/check_text.js` の表から読みます。
横断で止めるのは、音便に「ました」を繋いだ形、助詞を活用させた形、否定の「ない」を替えた形です。
これは、同じ運営者の横断の検査が止めている形と同じです。
である調へ書き換えたときの形は、正誤の記録が誤りの証拠として引いているので、横断では止めません。

## 雛形の固め方

呼ぶ側の雛形は、このリポジトリのコミットの値でワークフローを呼びます。
検査は、雛形の値のコミットのワークフロー・道具・目録が、いまのものと一字一句同じことを見ます。
そのため、それらを変えたあとには、雛形の値を上げるコミットが要ります。
Dependabot が shared-check.yml のアクションの値を上げる PR も、同じ理由で、雛形の値を上げるコミットが同じ枝に入るまで、検査の「呼ぶ側の雛形」で落ちます。
マージはマージコミットで行います。
squash や rebase をすれば、雛形の値のコミットが main の履歴から消えるためです。
